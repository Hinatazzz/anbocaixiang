# 上班族每月定投记录 · guojunchen.cn

一个记录个人基金定投的静态网站。从 **2026 年 8 月 11 日**开始，每月固定一笔钱投指数基金，
网站记录我的定投计划、持仓变化和踩过的坑，同时挂一份基金基础知识手册给自己随时翻。

线上地址：**<https://guojunchen.cn/>**

> 本站仅作个人记录与学习备忘，**不构成任何投资建议**。基金不保本，投资有风险。

## 这个站在做什么

| 我想解决的问题 | 网站上的做法 |
| --- | --- |
| 定投了多久？坚持几天了 | 首页顶部自动计算「第 N 天」，从 2026-08-11 起按本地日期实时算 |
| 钱投去哪了、为什么这么配 | 「定投计划」三个卡片：为什么选定投 / 我定投什么 / 我的规矩 |
| 现在赚了还是亏了 | 「持仓表」用 A 股习惯配色：**红 = 盈利，绿 = 亏损** |
| 别再犯同样的错 | 「常见误区」列了我自己踩过和差点踩的坑 |
| 想查个概念 | 「记录本」＋基金知识手册 |

### 关于天数

天数**不是写死的数字**，而是打开页面那一刻用 JavaScript 现算：

```
第 1 天 = 2026-08-11
第 N 天 = floor(今天 − 2026-08-11) + 1
```

所以这个页面哪怕一年不更新，打开看到的仍是正确的「第 N 天」。
如果以后想改起点，只改一处即可 —— 页面底部 `<script>` 里的 `DCA_START`。

## 页面功能

### 单页结构（锚点导航）

| 锚点 | 区块 | 内容 |
| --- | --- | --- |
| `#home` | 英雄区 | 第 N 天徽章、一句话说明、两个跳转按钮 |
| `#plans` | 定投计划 | 为什么选定投 / 我定投什么 / 我的规矩 |
| `#holdings` | 持仓表 | 基金名称、类型、持有金额、仓位、累计盈亏、收益率 |
| `#mistakes` | 常见误区 | 6 条踩坑提醒 |

### 配色约定

页面遵循 **A 股习惯**，与欧美相反，看的时候不要搞反：

-  **红色 = 涨 / 盈利** → `.up { color:#ff2d78 }`
-  **绿色 = 跌 / 亏损** → `.down { color:#00e39a }`

赛博朋克主题下这两个色值也做了霓虹化处理，但**语义仍是红涨绿跌**。

### 移动端

标题字号用 `clamp()` 自适应，窄屏下自动收缩；持仓表外层套 `overflow-x:auto`，
手机上左右滑动看完整表格，不会把页面撑破。
iPhone Safari 打开后可「添加到主屏幕」，当成一个小应用用。

## 本地查看与修改

### 直接打开

双击 `index.html` 即可在浏览器里看。所有内容都在单个文件里，没有构建步骤、没有依赖。

### 改内容

用文本编辑器打开 `index.html`，按注释找到对应区块直接改：

| 想改什么 | 改哪里 |
| --- | --- |
| 定投起点日期 | 底部 `<script>` 的 `DCA_START = new Date(2026, 7, 11)`（月份从 0 开始，7 = 8 月） |
| 持仓数据 | `#holdings` 区块里的 `<table>`，一行一只基金 |
| 涨跌颜色 | 该行加 `class="up"`（红）或 `class="down"`（绿） |
| 定投计划 / 误区 | `#plans` / `#mistakes` 区块的卡片文字 |
| 站名或标题 | `<title>` 标签、`.brand`、`<h1>` |

### 换回其他风格

把 `site_themes/` 里另两个变体的内容复制进 `index.html` 即可。三个变体共用同一套
区块结构和同一段天数计算脚本，只是 `<style>` 不同。

## 部署方式

本站托管在 **GitHub Pages**，并通过 **Cloudflare** 做 DNS 解析到自有域名
`guojunchen.cn`。仓库根目录的 `CNAME` 文件值为 `guojunchen.cn`，Pages 源设为
`main` 分支根目录 `/`。

### 发布流程（REST API 方式）

不依赖 `git push`，直接调 GitHub Contents API 提交文件，更适合网络受限的环境：

```bash
# 1. 生成 base64 内容
# 2. 取当前文件的 sha（更新时必须带）
# 3. PUT /repos/{owner}/{repo}/contents/{path}
```

关键参数：

- `owner` / `repo`：`Hinatazzz` / `anbocaixiang`
- `path`：`index.html`
- `body`：`{ "message": "...", "content": "<base64>", "sha": "<现有文件 sha>" }`
- 认证：`gh auth token` 取到的 `gho_` 开头的 OAuth token

提交成功后 **30~60 秒**生效，然后访问 `https://guojunchen.cn/` 验证。

###  两个必须注意的坑

**1. 不要把整个 `E:\下载\WorkBuddy` 当发布源。**
那个目录里有影片命名资料库、改名清单等私人文件，会把隐私内容一起传上去。
发布时**只传 `index.html` 这一个文件**（或单独建一个干净的发布目录）。

**2. 国内网络下 `github.com` 常被解析到被封的 IP。**
表现为 `gh` 登录报 `unexpected EOF`、`git push` 卡死。
诊断方法：`nslookup github.com`，如果返回 `20.205.243.166` 这类超时 IP 就是中了。
解决办法是在 `hosts` 里固定一个可用 IP（如 `140.82.112.3 github.com`），
然后 `ipconfig /flushdns`。（`api.github.com` 通常不受影响，所以 API 方式比 push 稳。）
