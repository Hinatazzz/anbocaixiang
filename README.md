# 上班族每月定投记录 · guojunchen.cn

一个记录个人基金定投的静态网站。从 **2026 年 8 月 11 日**开始，每月固定一笔钱投指数基金，
网站记录我的定投计划、持仓变化和踩过的坑。

线上地址：**<https://guojunchen.cn/>**

> 本站仅作个人记录与学习备忘，**不构成任何投资建议**。基金不保本，投资有风险。
> 页面中的持仓与行情均为**模板示例数据**，不是真实持仓。

---

## 这个站在做什么

| 我想解决的问题 | 网站上的做法 |
| --- | --- |
| 定投了多久？坚持几天了 | 首页顶部「第 N 天」自动计算，从 2026-08-11 起按本地日期实时算 |
| 现在几点、市场开没开 | 报头右侧实时时钟 + A股 / 港股 / 美股 三市场状态灯 |
| 钱投去哪了、为什么这么配 | 标签页「02 定投计划」：为什么选定投 / 我定投什么 / 我的规矩 |
| 现在赚了还是亏了 | 标签页「01 持仓」：七列表格 + 手机卡片，A 股习惯配色 |
| 别再犯同样的错 | 标签页「03 常见误区」列了我自己踩过和差点踩的坑 |

### 关于天数

天数**不是写死的数字**，而是打开页面那一刻用 JavaScript 现算：

```
第 1 天 = 2026-08-11
第 N 天 = floor(今天 − 2026-08-11) + 1
```

所以这个页面哪怕一年不更新，打开看到的仍是正确的「第 N 天」。
如果以后想改起点，只改一处即可 —— 页面底部 `<script>` 里的 `DCA_START`。

### 设计系统（账簿式排版）

整体复刻自开源项目 `Naka152/fund-ledger` 的总览版式：**纸色底、墨色字、细线分隔、直角、无渐变无阴影**。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--paper` | `#f2efe8` | 暖白纸底 |
| `--paper-2` | `#e8e4d9` | 次底色（提示条底） |
| `--ink` | `#151513` | 墨色正文 / 4px 分隔粗线 |
| `--ink-2` / `--ink-3` | `#4b4943` / `#8b877d` | 次级 / 弱化文字 |
| `--hair` | `#cdc7b9` | 1px 细线 |
| `--mark` | `#f3c316` | 高亮黄（hover、选中、扣款点） |
| `--up` / `--down` | `#c42a1f` / `#127a3e` | **红涨 / 绿跌**（A 股习惯） |
| `--f-disp` | Plex Condensed | 大数字标题（54px 总资产、20px 区块标题） |
| `--f-num` | Plex Mono | 等宽数字（tabular-nums，表格对齐） |

页面通过 `<html data-theme="light">` **固定为暖白浅色**，不跟随系统深色模式，
保证任何设备上看到的都是同一版纸面账簿。字体走本站 `/fonts/` 自托管（SIL OFL 许可证，随仓库附带 `OFL.txt`），
不依赖第三方 CDN，国内访问稳定。

### 移动端

- 窄屏（≤860px）持仓表自动切换为**卡片列表**，一行一只基金，三格小数据；
- 四格总览在 ≤1080px 变三列、≤860px 变两列，走势图独占一行；
- ≤640px 进一步压缩字号与内边距，标签页字号降到 18px；
- iPhone Safari 打开后可「添加到主屏幕」，当成一个小应用用。

## 本地查看与修改

### 直接打开

双击 `index.html` 即可在浏览器里看。除了 `fonts/` 里的字体文件外没有任何依赖，
没有构建步骤、不联网也能正常显示（字体加载失败会回退到系统等宽字体）。

### 改内容

用文本编辑器打开 `index.html`，按注释找到对应区块直接改：

| 想改什么 | 改哪里 |
| --- | --- |
| 定投起点日期 | 底部 `<script>` 的 `DCA_START = new Date(2026, 7, 11)`（月份从 0 开始，7 = 8 月） |
| 持仓数据 | `#panel-hold` 里的 `<table>`，一行一只基金；`data-g` 是分组、`data-v` 是金额、`data-p` 是收益率（供筛选排序用） |
| 涨跌颜色 | 该行加 `class="up"`（红）或 `class="down"`（绿） |
| 定投计划 / 误区 | `#panel-plans` / `#panel-mistakes` 区块的文字 |
| 关注指数 | `.strip` 里的 `.strip-item`，一行一个指数 |
| 站名或标题 | `<title>` 标签、`.brand`、`<h1>` |
| 换字体 | `fonts/` 换文件 + 顶部 6 条 `@font-face` |

## 部署方式

本站托管在 **GitHub Pages**，并通过 **Cloudflare** 做 DNS 解析到自有域名
`guojunchen.cn`。仓库根目录的 `CNAME` 文件值为 `guojunchen.cn`，Pages 源设为
`main` 分支根目录 `/`。

### 发布流程（REST API 方式）

不依赖 `git push`，直接调 GitHub Contents API 提交文件，更适合网络受限的环境：

```bash
# 1. 生成 base64 内容
# 2. 取当前文件的 sha（更新时必须带）
# 3. PUT /repos/{owner}/{repo}/contents/{path}
```

关键参数：

- `owner` / `repo`：`Hinatazzz` / `anbocaixiang`
- `path`：`index.html`、`fonts/xxx.woff2` 等
- `body`：`{ "message": "...", "content": "<base64>", "sha": "<现有文件 sha>" }`
- 认证：`gh auth token` 取到的 `gho_` 开头的 OAuth token

提交成功后 **30~60 秒** 生效，然后访问 `https://guojunchen.cn/?v=<时间戳>` 验证
（带时间戳是为了穿透 Cloudflare 缓存）。

完整流程与踩坑记录见本地技能 `github-pages-publish`（`~/.workbuddy/skills/github-pages-publish/`）。

### 三个必须注意的坑

**1. 不要把整个 `E:\下载\WorkBuddy` 当发布源。**
那个目录里有影片命名资料库、改名清单等私人文件，会把隐私内容一起传上去。
发布时只传 `index.html` / `README.md` / `fonts/*`（或用单独一个干净的发布目录）。

**2. 文件里不能带 emoji。**
本站仓库的 Pages 构建器是 `build_type: legacy`（Jekyll），
遇到警示号（U+26A0）、黑星（U+2605）、对勾（U+2713）以及各类变体选择符（U+FE0F）
这类符号会直接 `Page build failed`，
症状是「文件推上去了、API 读回来是对的、线上却一直是旧版」。
提交前先过一遍 emoji 检查，命中就换成纯文本。

**3. 国内网络下 `github.com` 常被解析到被封的 IP。**
表现为 `gh` 登录报 `unexpected EOF`、`git push` 卡死。
诊断方法：`nslookup github.com`，如果返回 `20.205.243.166` 这类超时 IP 就是中了。
解决办法是在 `hosts` 里固定一个可用 IP（如 `140.82.112.3 github.com`），
然后 `ipconfig /flushdns`。（`api.github.com` 通常不受影响，所以 API 方式比 push 稳。）
